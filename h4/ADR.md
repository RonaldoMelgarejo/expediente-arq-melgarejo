# ADR
Se eligieron Observer y Strategy porque resuelven necesidades claras del sistema: Observer permite notificar cuando el inventario llega al stock mínimo, relacionado directamente con el RF5, y Strategy permite cambiar las reglas de descuento sin modificar la lógica principal. Los demás patrones se descartaron porque Factory se relaciona con la creación de avisos, Adapter sería necesario principalmente para integrar sistemas externos, Builder no es tan necesario para la estructura actual de OrdenVenta y Singleton no corresponde porque en el sistema pueden existir varias instancias de las clases principales.
